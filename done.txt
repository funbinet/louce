Here is the distilled pattern from the reference system and a concrete, LOuce-specific plan to implement it without copying the original HTML.

Right now in LOUCE, actions return HTML strings directly from Rust and the UI treats that as the only output format. Reports are stored only in memory, and the JSON/TXT buttons are placeholders. You can see this in action_card.dart, output_viewer.dart, navigation_state.dart, and reports_screen.dart. The Rust actions in api.rs and subdomain.rs return HTML, not structured data.

**Implementation plan**
1) Define a report data contract (raw output + normalized output)
- Add a Rust report payload type that carries `summary`, `findings`, `raw_output`, `execution_log`, `artifacts`, and `metadata`, plus a separate `html_report` field generated by a renderer.
- Update api.rs to return this payload instead of a plain HTML string.  
- Update the phase actions to return structured data instead of HTML in subdomain.rs, cloud.rs, and audit.rs.

2) Create a report renderer that turns raw output into HTML/JSON/TXT
- Build a dedicated report engine in Rust that accepts the raw payload and emits:
  - A full HTML document with LOuce branding (MidnightHacker theme and logo.png).
  - A JSON report string (clean and structured, not just a dump).
  - A TXT report string (human-readable, log-like).
- Keep HTML unique: new layout, LOuce palette, LOuce typography, LOuce logo placement. Avoid the JABBER look entirely.

3) Persist reports to disk and index them for the Reports Explorer
- Create a storage layer that saves HTML/JSON/TXT to outputs (or `outputSaveLocation` from navigation_state.dart).
- Write a small metadata JSON sidecar per report (id, action, timestamp, format, file size, tags, hash if needed).
- Store execution logs as attachments (JSON + TXT) alongside the report.

4) Update action execution to save reports automatically
- In action_card.dart, after completion:
  - Save the report in all required formats (HTML, JSON, TXT by default).
  - Add the metadata entry to the Reports Explorer list.
- Extend `ActionSession` in action_session_state.dart to hold the report payload instead of a plain HTML string.

5) Add output format toggle in the action view
- Use the existing JSON/TXT buttons in action_card.dart as a real view switcher.
- Keep `OutputViewer` for HTML in output_viewer.dart.
- Add a code viewer (e.g., `SelectableText` with monospace styling) for JSON/TXT.

6) Upgrade Reports Explorer to real persistence + multi-format viewing
- Load report metadata from disk at startup and keep the list persistent in navigation_state.dart.
- In reports_screen.dart, add:
  - Format toggle (HTML/JSON/TXT).
  - Download/export, edit, and delete actions.
  - Execution log pane from stored log attachments (via terminal_log.dart).

7) Add export pipeline for CSV/CVE when applicable
- Extend the report engine to export CSV and CVE only when the raw payload includes the necessary fields (avoid fake data).
- Expose export options in the Reports Explorer as format-dependent actions.

8) QA and acceptance checks
- Action completion always creates HTML/JSON/TXT files.
- Toggle switches rendering instantly without re-running actions.
- Reports persist across app restarts and appear in the explorer.
- HTML uses the LOuce logo and MidnightHacker theme, not JABBER visuals.
